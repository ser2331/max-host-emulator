# MAX Host

Стенд хоста мини-приложений MAX. Не клон мессенджера.

Миниапп открывается в iframe, в URL передаются `#WebAppData`, `#WebAppPlatform` и `#MaxHost=1`. Внутри iframe работает официальный `max-web-app.js`. Хост отвечает на `postMessage` так, как ответил бы клиент MAX на выбранной платформе: **web**, **desktop**, **android**, **ios**.

Текущая версия: **0.1.1**.

## Запуск

```bash
cd max-host-emulator
npm install
npm run dev
```

В другом терминале миниапп: `npm run dev` на `https://localhost:5173`.

Откройте `https://127.0.0.1:4173`, вставьте URL миниаппа и токен бота (для валидного `initData`).

## Ограничения эмуляции

MAX Host повторяет контракт Bridge и platform-specific поведение хоста, но не всегда может повторить нативную среду устройства 1:1.

### Storage в dev

Для локальной разработки mini app внутри `MAX Host` может использовать обычный `browser localStorage` вместо bridge `DeviceStorage`/`SecureStorage`.

Это осознанное упрощение для dev-цикла:

- убирает таймауты bridge storage в локальном iframe
- ускоряет cold start и refresh mini app
- делает стабильнее сценарии авторизации с сохранением access token

При этом такое поведение **не идентично** реальному Android / iOS клиенту MAX:

- не эмулирует нативный storage layer ОС
- не воспроизводит тайминги и сбои bridge storage
- не заменяет финальную проверку на реальных клиентах MAX

Итого: для логики mini app и auth-flow этого достаточно, но для проверки fidelity именно `DeviceStorage` нужен реальный MAX-клиент или отдельная нативная оболочка хоста.

### Запуск на телефоне

MAX Host можно открыть на телефоне через браузер, если отдать его не на `127.0.0.1`, а на LAN IP компьютера или через tunnel.

Пример:

- ПК: `https://192.168.x.x:4173`
- mini app: `https://192.168.x.x:5173`

Но даже на телефоне в браузере это всё ещё будет **веб-эмулятор**, а не настоящий клиент MAX. Значит:

- можно тестировать мобильный viewport, touch-flow, layout и web storage на устройстве
- нельзя получить настоящий нативный `DeviceStorage`, `SecureStorage`, биометрию, NFC и другие mobile API только за счёт открытия `127...`/LAN URL в мобильном браузере

Чтобы поведение storage и native API было максимально близко к Android / iOS, нужен не просто сайт, а нативная оболочка (`WebView` / `WKWebView` / `Android WebView`) с собственным bridge поверх эмулятора.
